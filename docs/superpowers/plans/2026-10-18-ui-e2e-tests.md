# End-to-end UI Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Playwright-style harness that drives the real client headless (cursor, clicks, keys, typed text, screenshots), and tests that cover every screen of the current UI.

**Architecture:** `main.rs` hands its wiring to `app::add_client`, which the harness calls too, so tests run the app the player runs. The harness owns an `App` with a surfaceless primary `Window` (cursor and resolution for `ui_focus_system`), injects input as `MouseButtonInput` / `KeyboardInput` / `MouseWheel` messages, finds elements by visible text, `Name` or marker, and points the cameras to an image to take a picture. Journeys in game go through the real integrated server, on wall-clock time.

**Tech Stack:** Rust nightly (`rust-toolchain.toml`), Bevy 0.19, bevy_simple_text_input 0.15, renet, lavapipe (`vulkan-swrast` / `mesa-vulkan-drivers`), `image` 0.25, `tempfile` 3.

**Spec:** `docs/superpowers/specs/2026-10-18-ui-e2e-tests-design.md`

## Global Constraints

- No test encodes a defect listed in the spec's non-goals. A coverage line found broken by a defect missing from that list becomes `#[ignore = "defect: …"]` with the intended behaviour, and is reported.
- The only change of the screens is adding `Name` components to elements without text (Task 4, Task 6), plus making private items `pub(crate)` where a test needs them.
- Every test is `#[cfg_attr(not(target_os = "linux"), ignore = "needs lavapipe")]`, like `client/src/ui/hud/inventory/goldens.rs`.
- Each harness gets its own temporary game folder (`tempfile::TempDir`); no fixed network port.
- `just check` (fmt, clippy `-D warnings`, `cargo test --workspace`) passes at the end of every task. The suite adds at most about 2 minutes to `cargo test --workspace`.
- Code style: doc comments in full sentences like the surrounding code, tests named as sentences, commits in Conventional Commits (`test(client): …`, `refactor(client): …`).
- `client/src/ui/recon_spike.rs` and its `mod` line in `client/src/ui/mod.rs` are a throwaway spike: delete them in Task 1, keep what they teach (below).
- Spike findings: cameras need `IsDefaultUiCamera` (the harness inserts it on every `Added<Camera>`), otherwise the UI has no camera while they render to the image; one frame must run after each change of `RenderTarget` before reading positions or clicking. `UiGlobalTransform::translation` is the centre of a node in physical pixels; the window's scale factor is 1.

## Review Focus

1. A locator whose text exists only in a hidden dialog (e.g. "Resume" while the pause menu is hidden) → not found; hidden elements never match. (Task 2 test `a_hidden_text_is_not_found`)
2. A text split into spans (the debug overlay's "FPS: " + value) → matched on its full content. (Task 2 test `a_text_is_matched_with_its_spans`)
3. A wait whose condition never holds → the test fails after its timeout with what it waited for, never hangs. (Task 2 test `waiting_for_what_never_happens_fails_with_its_description`)
4. A test that ends in game → the harness leaves the game when dropped, so the integrated server thread stops and saves before the next test. (Task 7 test `dropping_the_harness_in_game_stops_the_local_server`)
5. Two harnesses running at once (cargo runs tests in parallel) → separate folders and ports, no interference. (Task 4 test `two_harnesses_run_side_by_side`)

### Task 2: Locators, clicks, keys and typed text

**Files:**
- Create: `client/src/e2e/locator.rs`, `client/src/e2e/input.rs`
- Modify: `client/src/e2e/mod.rs`

**Interfaces:**
- Consumes: Task 1 `Harness`.
- Produces:
  - `pub struct Locator` with constructors `pub fn text(content: &str) -> Locator`, `pub fn name(name: &str) -> Locator`, `pub fn marker<C: Component>() -> Locator`, `pub fn row(content: &str) -> Locator`, and `pub fn within(self, scope: Locator) -> Locator`.
    - `text` matches a visible `Text` whose content, concatenated with its `TextSpan` children, equals `content`.
    - `row(content)` is the nearest ancestor of `text(content)` that holds at least one other `Text` or a `Button`.
    - Visible means `InheritedVisibility` true, `Display` not `None` up the tree, and a node of non-zero size.
  - On `Harness`: `fn find(&mut self, locator: &Locator) -> Vec<Entity>`, `fn get(&mut self, locator: &Locator) -> Entity` (exactly one, else panics listing the visible texts), `fn is_visible(&mut self, locator: &Locator) -> bool`, `fn text_of(&mut self, locator: &Locator) -> String`, `fn center_of(&mut self, locator: &Locator) -> Vec2`.
  - Input on `Harness`: `fn click(&mut self, locator: &Locator)`, `fn right_click(&mut self, locator: &Locator)`, `fn hover(&mut self, locator: &Locator)`, `fn press(&mut self, key: KeyCode)` (press frame, then release frame), `fn key_down(&mut self, key: KeyCode)`, `fn key_up(&mut self, key: KeyCode)`, `fn type_text(&mut self, text: &str)`, `fn scroll(&mut self, lines: f32)`.
    - A click moves the window cursor (`set_physical_cursor_position`) to `center_of`, runs one frame for hover, writes `MouseButtonInput` Pressed, runs a frame, writes Released, runs a frame.
    - `type_text` writes, per character, a `KeyboardInput` with `logical_key: Key::Character(c)` (`Key::Space` for a space), `text: Some(c)`, the matching `KeyCode` for ASCII letters and digits (`KeyCode::Unidentified(NativeKeyCode::Unidentified)` otherwise), pressed then released, one frame each.
    - Never call `ButtonInput::press` directly: `InputPlugin` rebuilds it from the messages every frame.

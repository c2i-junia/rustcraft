# Hub and hosted worlds — design

Approved proposal: "Hub v1 et royaumes" (25 November 2026), itself following "Le hub
rustcraft.dev". This spec is the binding version, in English, with the open questions decided.

## Goal

A central service, the **hub**, at `https://hub.rustcraft.dev`, open source and replaceable:

1. Players create an account (username + password) and log in **from the game**.
2. The hub signs a short-lived **certificate** for a key generated by the game on each device.
   A server checks a player by that certificate and a signed challenge, **without calling the
   hub** for each join.
3. Accounts the admin trusts (role `host`) create **hosted worlds**: game servers the hub starts
   on the VPS on demand, for the members their owner invites.

The default hub address is compiled into the game; `--hub <url>` changes it. Servers launched
by hand stay `--auth offline` by default (today's behaviour).

## Decisions on the open questions

| Question | Decision |
|---|---|
| Name of the feature | **Hosted worlds** in the UI. `realm` in code, API and database. |
| Usernames | 3 to 20 characters of `A-Z a-z 0-9 _`, unique case-insensitively, original case kept. |
| Recovery code | Mandatory, shown once at sign-up, replaced each time it is used. |
| Idle hosted worlds | Stop after **10 minutes** with no player. |
| Servers started by hand | `--auth offline` by default. |
| Version of a hosted world | The hub's configured image at each start: a world is upgraded at its next start. |
| Mods in hosted worlds | None in v1. |

## Repository layout

```
Cargo.toml                 game workspace: shared, client, server, crates/protocol; exclude = ["hub"]
crates/protocol/           rustcraft-protocol: no Bevy
hub/                       separate cargo workspace and Cargo.lock
  Cargo.toml               [workspace] members = [".", "realm-agent"]; package rustcraft-hub
  migrations/              sqlx migrations, applied at start
  src/                     binary rustcraft-hub (subcommands `serve`, `admin …`)
  realm-agent/             binary rustcraft-realm-agent
  Dockerfile               targets `hub` and `realm-agent`, build context = repository root
  compose.yaml, realm-agent.example.toml, README.md
```

- The hub uses **the repository's pinned nightly toolchain** (`rust-toolchain.toml` at the
  root): the root `.cargo/config.toml` uses nightly-only options and cargo applies it to
  `hub/` too. It is still a separate project: its own workspace, lockfile and CI job.
- `rustcraft-protocol` holds what the game and the hub share, with no Bevy dependency:
  - `identity`: `Certificate`, `SignedCertificate`, signing and verification, the join
    signature, key encodings.
  - `api`: the JSON request and response types of the hub API, and the error codes.
  - `status`: the status packet codec, **moved from `shared/src/status.rs`** (re-exported by
    `shared` so the game's code does not change).
  - `DEFAULT_HUB = "https://hub.rustcraft.dev"`.

## Identity

- **Keys:** Ed25519 (`ed25519-dalek` 2). The hub's signing key is a 32-byte seed in a file,
  hex-encoded, read at start; its id `hub_key_id: u8` (1 for the first key) is in the
  certificate. `GET /.well-known/rustcraft-hub` publishes every accepted key.
- **Certificate** (encoded with `postcard`, signed over those exact bytes):
  `version: u8 (1)`, `hub: String` (the hub's public URL), `id: Uuid` (certificate id),
  `account: Uuid`, `name: String` (display name), `device_key: [u8; 32]`, `issued_at: u64`,
  `expires_at: u64` (Unix seconds), `hub_key_id: u8`.
  `SignedCertificate { bytes: Vec<u8>, signature: [u8; 64] }`; verification decodes `bytes`
  only after the signature checks.
- **Validity:** 7 days. The game renews it once half its life has passed.
- **Join signature:** the device key signs `b"rustcraft-join-v1" ‖ nonce (32 bytes) ‖
  server_key (32 bytes) ‖ address`, where `address` is the address the player dialed,
  normalized (`normalize_address`: host in lower case without a trailing dot, IPv6 in
  brackets, port explicit, 8000 by default), and sent in the proof. A hub-mode server takes
  only proofs for one of its `--public-address` values (at least one is required), so a server
  that relays another's challenge to its players gets proofs worth nothing there.
- **Certificate check:** besides the hub's keys, the server compares `cert.hub` with its hub's
  URL (trailing `/` ignored).
- **Server key:** each hub-mode server has an Ed25519 key in `<game folder>/server_key.ron`,
  created at first start (offline servers and solo worlds use a throwaway key).
- **Revocation:** `GET /v1/revoked` lists the ids of revoked certificates that have not expired.
  A hub-mode server reads it at start and every hour (every 5 minutes after a failed read, until
  one succeeds) and refuses those certificates; players online with a certificate revoked since
  are dismissed.
- **Pre-authentication timeout:** in every mode, a connected client that has not joined 5 s
  after connecting is dismissed. Netcode runs `Unsecure`: a client announces its id, so someone
  reconnecting in a loop with a player's id can still keep that player out; netcode connect
  tokens issued by the hub are the real fix, left for later.
- **Hub URLs:** `--hub` takes `https://` URLs, and `http://` only to a loopback host.

## Accounts

- Username rules above. Reserved names (case-insensitive): `admin`, `administrator`,
  `rustcraft`, `hub`, `server`, `moderator`, `mod`, `support`, `system`, `root`, `owner`,
  `staff`, `official`.
- Password: 10 to 128 characters (counted in `char`s), no composition rule, refused when it
  contains the username (case-insensitively) or when the `zxcvbn` crate scores it below 2
  (of 4) with the username as a user input. `zxcvbn` embeds its own lists of common
  passwords and words, so no list is downloaded or kept in the repository.
- Hash: Argon2id `m = 19456 KiB, t = 2, p = 1`, PHC string. The recovery code is hashed the
  same way.
- Recovery code: `RCV-` + 3 groups of 5 characters from the Crockford base32 alphabet
  (`0-9 A-Z` without `I L O U`), e.g. `RCV-7K2QF-M9XWA-4HTPE`; input is case-insensitive and
  ignores spaces and dashes.
- Session: 32 random bytes, sent as base64url without padding; the hub stores SHA-256 only.
  Lifetime 90 days, extended on every use. Header `Authorization: Bearer <token>`.
- Changing the password, or using the recovery code, revokes every other session and every
  certificate of the account.
- `DELETE /v1/me` (password required) deletes the account: status `deleted`, username freed
  after 30 days, sessions and certificates revoked, owned hosted worlds archived.

## Database (Postgres 17)

Tables as in the proposal: `accounts` (with `citext` username, `display_name`, `status`,
`realm_quota`), `account_roles` (`admin`, `host`), `account_identities` (`provider`, `subject`;
v1 only `password`, `subject` = account id), `password_credentials` (`password_hash`,
`recovery_hash`), `sessions`, `certificates`, `signups` (`ip_key` = HMAC-SHA256 of the IPv4
address or of the IPv6 /64 with a hub secret, purged after 30 days), `audit_log`, `realms`,
`realm_members`. Queries use sqlx at runtime (`sqlx::query_as` with `FromRow`), not the
compile-time macros, so building needs no database.

## Rate limits

| Action | Limit | Beyond |
|---|---|---|
| Sign-up, per IPv4 address or IPv6 /64 | 10 per hour and 30 per day | 429 `rate_limited` + `Retry-After` |
| Sign-up, whole hub | 200 per hour | 503 `signups_closed` |
| Sign-up from a trusted range (config) | 60 per hour | 429 |
| Failed logins per (username, IP) | 5 per 15 min | 429 |
| Failed logins per IP | 30 per 15 min | 429 |
| Concurrent Argon2 computations | max(1, cores / 2) | queued |
| Certificates per account | 30 per hour | 429 |
| Hosted world starts per world | 10 per hour | 429 |

Sign-ups are counted in Postgres; the others in memory. The client IP is the TCP peer, or the
last address of `X-Forwarded-For` when the peer is `127.0.0.1`/`::1` (Caddy).

## Hub API

JSON over HTTPS. Errors: `{"error": "<code>", "message": "<English sentence>"}` with codes
`invalid_username`, `username_taken`, `invalid_password`, `weak_password`, `bad_credentials`,
`rate_limited`, `signups_closed`, `unauthorized`, `forbidden`, `not_found`, `quota_reached`,
`no_free_slot`, `invalid_request`, `internal`.

| Route | Access | Purpose |
|---|---|---|
| `GET /.well-known/rustcraft-hub` | public | `{name, url, api_version: 1, keys: [{id, public_key (hex)}], protocol_id}` |
| `POST /v1/accounts` | public | `{username, password, device_name?}` → `{account, session, recovery_code}` |
| `POST /v1/sessions` | public | `{username, password, device_name?}` → `{account, session}` |
| `DELETE /v1/sessions/current`, `DELETE /v1/sessions` | session | log out here / everywhere |
| `POST /v1/recovery` | public | `{username, recovery_code, new_password}` → `{account, session, recovery_code}` |
| `GET /v1/me` | session | `{id, username, roles, realm_quota, created_at}` |
| `PUT /v1/me/password` | session | `{current_password, new_password}` |
| `DELETE /v1/me` | session | `{password}` |
| `POST /v1/certificates` | session | `{device_key (hex)}` → `{certificate (base64 of bytes), signature (base64), expires_at}` |
| `GET /v1/revoked` | public | `{ids: [uuid]}` |
| `GET /v1/profiles?name=` | public | `{id, username}` |
| `GET /v1/realms` | session | the worlds owned or joined, with state, address, members |
| `POST /v1/realms` | session, `host` | `{name, settings}` within `realm_quota` |
| `POST /v1/realms/{id}/start` | member | starts it if stopped → `{state, host, port}` |
| `POST /v1/realms/{id}/stop` | owner | |
| `PUT /v1/realms/{id}/members/{username}` | owner | `{role: member|operator}` |
| `DELETE /v1/realms/{id}/members/{username}` | owner | |
| `DELETE /v1/realms/{id}` | owner | archive |
| `GET /v1/realms/{id}/config` | the world's server (realm token) | `{members: [{id, username, role}], owner}` |

Admin is a CLI only: `rustcraft-hub admin grant <user> host [--realms N]`, `revoke <user> host`,
`suspend <user> --reason`, `unsuspend <user>`, `reset-password <user>` (prints a temporary
password), `realms`, `users`.

## Game changes

- `shared`: `AuthChallenge { nonce: [u8; 32], server_key: [u8; 32], hub: Option<String> }`
  sent by the server on connect; `AuthRegisterRequest` gains `proof: Option<JoinProof>`
  (`certificate`, `signature`). `PROTOCOL_ID` is bumped.
- `server`: `--auth hub|offline` (default `offline`), `--hub <url>` (default `DEFAULT_HUB`),
  `--realm <uuid>` with env `RUSTCRAFT_REALM_TOKEN` (hosted world mode). In hub mode a player
  needs a valid proof; their `PlayerId` is derived from the account UUID (its first 8 bytes,
  little-endian), the player file is `players/<uuid>.ron`, and `ops.ron`, `banned.ron`,
  `whitelist.ron` store `{id, name}` entries (names in offline mode, as today). In hosted
  world mode the whitelist and operators come from `GET /v1/realms/{id}/config`, read at
  start and every 60 s; the owner is always an operator.
- `client`: Account screen from the main menu; `account.ron` (mode 0600 on Unix) with the hub
  URL, session token, device key, last certificate; renewal in the background; the session's
  username becomes the player's name; a Hosted worlds tab in Multiplayer; `--hub <url>`.
  HTTP with `ureq` (rustls) in Bevy's `IoTaskPool`; no tokio in the game.
- Preparations (useful on their own): save then exit on SIGTERM and Ctrl-C; `--seed`,
  `--world-type`, `--game-mode`, `--difficulty` for a new world; `--max-players`
  (default 64); the Dockerfile exposes the status port and runs as a non-root user with the
  game folder in `/data`.

## Hosted worlds

- **Who:** creating needs role `host` and `realm_quota` > number of non-archived owned worlds.
  Any member can start a world and join it; the owner manages members, stops and archives.
- **Lifecycle:** `stopped → starting → running → stopping → stopped`, `failed` after 60 s
  without an answer on the status port, `archived` on delete (volume renamed, removed after
  30 days).
- **Idle stop:** the hub probes each running world's status port every 30 s; 10 minutes at 0
  players stops it.
- **Agent:** the only component with `docker.sock`. It listens on a Unix socket shared with the
  hub and accepts newline-delimited JSON requests: `start {realm, slot, token, settings}`,
  `stop {realm}`, `status {realm}`, `archive {realm}`. It fixes the image, limits, ports and
  security options from its own config file, never from the request.
- **Container:** image from the agent config; memory 1.5 GB, 1.5 CPUs, 256 pids (config);
  `--max-render-distance 12`, `--max-players 10`; slot `n` publishes UDP `25000 + 2n` and
  `25001 + 2n` (game, status) on IPv4 and IPv6; 20 slots; read-only root filesystem, the
  world on volume `rustcraft-realm-<uuid>` at `/data`; `cap_drop ALL`,
  `no-new-privileges`, non-root user; stop with SIGTERM and 30 s grace; at most 3 running
  worlds (hub config).
- **Address:** `play.rustcraft.dev` and the slot's game port.

## Deployment

- DNS (done): `hub.rustcraft.dev` and `play.rustcraft.dev`, A and AAAA, not proxied.
- `compose.yaml`: `db` (postgres:17, internal network only), `hub` (published on
  `127.0.0.1:8080` only), `realm-agent` (`docker.sock`, `network_mode: none`). Secrets in
  files.
- Caddy: `hub.rustcraft.dev { reverse_proxy 127.0.0.1:8080 }`.
- Firewall: a `DOCKER-USER` rule only lets in UDP 25000–25039 to published container ports.
- Backups: nightly `pg_dump`.
